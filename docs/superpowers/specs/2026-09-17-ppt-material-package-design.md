# RoboFuzz 项目 PPT 完整素材包设计

## 目标

生成一套可直接交给师兄作为 PPT 内容来源的完整材料包。材料包不制作逐页 PPT 精简稿，而是尽可能完整地归集本人已经完成的工作、可核实成果、量化实验数据、开题指标对应关系、公开 Issue、成果边界及证据位置，并提供可直接用于 PPT 的图片资产。

## 交付目录

材料包输出到独立目录 `deliverables/robofuzz_ppt_materials_2026-09-17/`，最终同时生成 ZIP 压缩包。目录包含：

1. `00_README.md`
   - 说明材料包用途、阅读顺序、统计时点和成果口径。
   - 明确“错误轮次、Oracle 标签、公开 Issue、独立根因、确认漏洞”不能混用。

2. `01_PPT_MATERIALS_MASTER.md`
   - 项目背景、问题定义、三大挑战、三条技术路线。
   - 本人工作在项目总体路线中的位置。
   - 原始 RoboFuzz 与本人增量的源码级对照。
   - 规范获取、预处理、SpecBlock、OracleIR、Agent、可执行 Oracle 全链路。
   - 语义种子、变异、反馈、SeedQueue 和目标运行契约。
   - Foxy 与 Jazzy 两阶段演进。
   - TurtleBot3、PX4、MoveIt、TurtleBot4、MoveIt2、SLAM、Nav2 的逐平台实验与成果。
   - 公开 Issue、候选根因、外部反馈和证据等级。
   - 六项正式指标逐项判断。
   - 已完成、部分完成、尚未完成、项目组既有基础的边界。
   - 可直接引用的成果表述、禁用表述和下一阶段重点。

3. `02_PPT_EVIDENCE_INDEX.md`
   - 为每项关键数字和结论提供本地文件、源码行号、实验报告、日志目录或公开 Issue 链接。
   - 标注证据类型、可信等级、能证明什么、不能证明什么。
   - 区分 Git 已跟踪文件、工作区本地生成物和未提交修改。

4. `03_PPT_DATA_TABLES.md`
   - 提供可复制到 Excel/PPT 的规范块与 OracleIR 数据、平台矩阵、变异算子、实验结果、Issue 状态、六项指标状态等表格。
   - 表格中的统计值均注明统计时点和口径。

5. `04_PPT_CLAIM_AND_QA_GUIDE.md`
   - 汇总推荐标题、30 秒总述、1 分钟技术总述、典型问答。
   - 提供“可以说／需要限定／不能说”的成果措辞。
   - 说明原开题 PPT 与后续书面报告的版本差异，正式指标以书面报告为准。

6. `assets/`
   - 项目方法全链路图。
   - 开题三条路线与本人工作对应图。
   - 五个现代目标 SpecBlock/OracleIR 数量图。
   - 代表实验规模与结果概览图。
   - 六项指标完成状态图。
   - 各平台公开 Issue 开放/关闭状态图。
   - 每张图同时提供 SVG 和高分辨率 PNG，便于 PPT 使用和后续编辑。

## 证据和表述规则

材料按以下层级组织：

- **A：源码能力证据**——功能已实现，并有源码或测试支撑。
- **B：实验命中证据**——运行中出现 Oracle 命中，但尚未完成独立复现。
- **C：复算/回放证据**——离线复算、独立真值或回放仍能复现，并完成级联去重。
- **D：公开报告证据**——已向上游提交 Issue。
- **E：外部确认与编号证据**——维护者确认、修复合入或获得 CNVD/CNNVD 编号。

同一结果可同时具有多个等级，但不会把低等级证据写成高等级结论。公开 Issue 数不等于独立漏洞数；开放或带 `bug` 标签也不等于维护者已经确认根因。

## 统计和版本口径

- 指标、阶段和成果形式以 `/home/ymc/下载/2-开题报告 - 涛(1).doc` 为正式基线。
- `/home/ymc/下载/具身智能逻辑错误挖掘-1.28.pptx` 用于恢复早期设计意图，并单列其与书面报告的差异。
- 个人成果只统计可由源码、Git、容器、日志、分析文档或本人公开 Issue 交叉验证的内容。
- Unitree Go2 既有漏洞、CNNVD 申请、平台设备、论文和专利等若缺少个人归属证据，归为项目组基础或项目总体目标，不计入本人已完成成果。
- 当前工作区存在未提交修改和被 `.gitignore` 忽略的生成物；材料会明确写成“当前工作区已生成/验证”，不会写成“均已提交”。

## 图片设计

- 采用适合白底汇报的蓝—青主色，完成项、部分完成项、待完成项分别使用绿色、橙色和灰红色。
- 所有图表直接标注数值，图下注明统计口径。
- 图中避免使用“发现漏洞数”统称不同证据层级；实验命中、候选根因和公开 Issue 分开显示。
- 所有 PNG 以至少 1600 像素宽导出；SVG 保留可编辑文本与矢量元素。

## 验收检查

生成后进行以下检查：

1. 六项指标原文、完成判断和证据是否一致。
2. SpecBlock、OracleIR、轮次、错误帧、Issue 状态等数字是否能回溯到来源。
3. 是否错误地把项目组基础、原始 RoboFuzz 能力或尚未实现的 IPDG/虚实差分算作个人成果。
4. Markdown 中引用的本地文件和图片是否存在。
5. SVG/PNG 是否可正常打开，文字是否清晰且没有裁切。
6. ZIP 是否包含完整目录，解压后不依赖 `/tmp` 文件。
