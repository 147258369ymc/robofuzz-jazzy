# RoboFuzz 阶段进展 PPT 内容说明

## 1. 交付范围与口径

成品文件仅包含汇报的第 2 部分“任务与指标完成情况”和第 3 部分“技术细节”，共 7 页。它以《拔尖人才项目阶段进展汇报.pptx》为版式模板，删除封面，保留原目录页版式和主题风格，重建指标表和四页技术内容。源模板未被修改。

成果表述遵循三条边界：公开 Issue 不直接等同于独立或已确认漏洞；结构化规范和 OracleIR 的数量不等同于全部已在线执行；TB4 组合优化数据反映输入多样性和重复度，不是“语义约束覆盖率”。

## 2. 逐页内容与讲解要点

### 第 1 页：第 2 部分目录

- 来源：模板第 2 页。
- 用途：进入“任务与指标完成情况”，目录中突出 02。
- 替换：“课题概要与研究内容”改为“课题概况与研究内容”，“年度进展与重要成果”改为“技术细节”。

### 第 2 页：任务与指标完成情况

- 来源：模板第 3 页的版式，页面内容重建。
- 表格为四列：指标名称、原始基线/立项状态、开题完成要求、当前指标状态。已按要求删除原来独立的“当前指标状态”列，并将最后一列扩展为较完整的证据说明。
- 六项指标的当前等级分别为：约束数量“达到数量规模”；四类输入“部分达到”；变异算子“达到：8 类”；偏轨判定与回溯“仿真侧达到”；覆盖率提升和平台/漏洞指标均为“待形成正式证据”。
- 讲解时要强调“状态是离散证据等级，不是完成百分比”，也不要把已有软件栈仿真实验说成已完成 Go2/ECO65-B 实物验证。

### 第 3 页：第 3 部分目录

- 来源：模板第 4 页。
- 用途：进入“技术细节”，目录中突出 03。
- 页面仅替换目录文字，不重建模板的背景、编号和版式。

### 第 4 页：三项重点技术任务与总体链路

- 来源：模板第 5 页的主题背景，页面内容重建。
- 主要难点：机器人的正确行为往往是隐含的；异常路径在高维状态空间中稀疏；逻辑偏轨通常不会让系统崩溃，难以直接判定。
- 方法：从系统规范中明确不同状态下应有的响应，用带控制语义的输入激活路径，再以仿真记录、离线复算和回放完成确认；验证结果反过来补充规则并调整输入。
- 边界：已形成跨 PX4、TurtleBot4、MoveIt2、SLAM 和 Nav2 的仿真侧原型，但五类目标的成熟度不一；实物差分与正式漏洞编号为下一阶段。

### 第 5 页：任务一——规范驱动的语义约束提取与行为 Oracle 构建

- 来源：模板第 6 页的主题背景，页面内容重建。
- 主要难点：文档、Launch/YAML、ROS 接口、源码和模型的形式不同，约束还可能分散在多个模块中，需要生成可执行且能追回原文的行为判据。
- 方法：先对多源规范分类处理，转为保留来源的 SpecBlock；再检索相关片段并生成结构化 OracleIR；最后由 Agent 结合目标话题、字段、状态机和时间窗补齐上下文，而不是把模型文本直接当作最终判定代码。
- 边界：151 份现代 OracleIR 并非都已逐条映射成在线 Oracle；复杂约束仍需目标专用上下文。

### 第 6 页：任务二——基于语义反馈的扰动输入生成与种子调度

- 来源：模板第 7 页的主题背景，页面内容重建。
- 主要难点：单字段随机变异很难激活持续性、时序性和物理耦合异常；无限保留相似种子又会浪费轮次。
- 方法：将一次字段变异扩展为有持续时间、先后顺序和模式变化的行为序列；每轮结束后结合运动/任务反馈、新颖性和数据质量调度种子，并用容量、次数、近似去重和陈旧淘汰限制重复。
- 边界：传感数据的专用连续扰动和通用延迟/丢包/乱序仍需补强；TB4 的 629→842 和 156→21 是组合优化结果，不是指标 5 所要求的语义约束覆盖率。

### 第 7 页：任务三——控制语义偏轨判定、证据回溯与根因归并

- 来源：模板第 8 页的主题背景，页面内容重建。
- 主要难点：系统可能不崩溃、不返回错误码，但运动或任务结果已偏离规范；异步多源观测和级联报警容易造成重复计数和错误归因。
- 方法：保存触发输入、Topic/Action/TF、任务状态、rosbag/ULG 和仿真真值；先做就绪、数据齐全性和时钟对齐门控，再在线判定；对候选异常进行离线复算和回放，根据输入、时间段和控制链关系去重并归并级联现象。
- 边界：“不可判定”不进入异常计数；报警帧、错误轮次、去重异常签名、候选根因族和独立漏洞是不同层级；34 条公开 Issue 与独立漏洞不是一一对应。

| 数字 | 定义 | 不能说成 |
|---|---|---|

| 2749 | 预处理形成的 SpecBlock 数 | 2749 条已上线 Oracle |
| 151 | 五个现代目标的 OracleIR 数 | 全部已在线执行的 Oracle |
| 35 | legacy 逻辑规格数，与 151 份现代 IR 分开统计 | 现代 IR 的一部分 |
| 5 类目标 | PX4、TurtleBot4、MoveIt2、SLAM、Nav2 | 5 类实物平台 |
| 8 类策略 | 多轴协同、方向翻转、持续块、边界推进、反转、轨迹弧、单点极值、回环 | 八项已经完成独立消融的算子 |

| 156→21（下降 86.5%） | TB4 组合优化中“最高单一输入签名重复次数”下降 | 整体报警减少86.5% |
| 928 | TB4 证据带中的测试轮次数 | 异常数、签名数或漏洞数 |
| 781 | 上述 TB4 数据中的签名数 | 与 928 或 224 可直接相加的同一统计单位 |

| 22 / 12 | 34 条 Issue 当时的 Open / Closed 状态数 | 22 个未修复漏洞 / 12 个已修复漏洞 |

928、781 和 224 分别是轮次、签名和帧级命中，统计单位不同，不能相加，也不能直接换算为漏洞数。

## 4. 不能在讲解中替换的表述

1. “151 份现代 OracleIR”不能替换为“151 条已执行 Oracle”。
2. “2749 个 SpecBlock”不能替换为“2749 条已执行约束”。
3. “629→842 的唯一输入签名增长”不能替换为“覆盖率提升 33.9%”。
4. “156→21”指最高单一输入签名重复次数下降，不是报警数或漏洞数下降。
5. 928、781、224 属于不同统计单位，不能直接比较或相加。
6. 34 是公开 Issue 数，不是独立漏洞数。Open/Closed 是 Issue 流转状态，不等于漏洞认定。
7. Go2/ECO65-B 实物验证和基于事件对齐的虚实差分属于下一阶段，尚未开展。
